Comprehensive User Guide

Step-by-step instructions for students, educators, and college administrators
Getting Started: SkillSum ResultSetu is a free educational utility by SkillSum Innovations designed to automate bulk academic result extraction from university portals. It runs without user registration, requires no software installation, and processes student lists locally in your web browser.
1

Step 1: Prepare Your Excel File

Prepare a standard spreadsheet containing your students' examination identifiers in .xlsx or .xls format.

  • Required Column: Student Enrollment Number or Roll Number.
  • Optional Columns: Date of Birth (required only if the target examination portal requires DOB authentication), Student Name, Branch/Department.

Example of a properly formatted student list:

Roll_No Student_Name DOB Branch
E2100456001 Amit Kumar 12/04/2003 Computer Science
E2100456002 Priya Sharma 25/08/2002 Electrical Engg
E2100456003 Rahul Singh 05/11/2003 Mechanical Engg
⬇ Download Ready Sample Excel Template
2

Step 2: Upload & Review Student List

Drag and drop your Excel file onto the upload zone or click to select the file from your computer or phone.

  • Browser-Side Local Parsing: The tool reads rows instantly in memory using client-side JavaScript. Your file does not leave your browser for preview.
  • Automatic Column Detection: Standard headers like Roll No, Enrollment, DOB, and Name are matched automatically. If your headers differ, use the dropdown selectors to map them manually.
  • Pre-Flight Quality Review: Inspect the summary chips for valid records, duplicate student rows, and empty rows. Duplicates are highlighted with row indicators.
3

Step 3: Enter University Result Portal URL

Paste the public URL of the college or examination board result page into the portal input field.

  • Click Validate Portal to confirm connector compatibility. The system indicates whether a specialized portal adapter (such as BTEUP) is active.
  • Authentication Notice: Portals protected by graphical CAPTCHAs, OTPs, or student credentials cannot be bypassed. The tool operates solely on open, public examination result lookup endpoints.
4

Step 4: Review Privacy Notice & Confirm

Before processing starts, a transparent consent modal details the exact data lifecycle:

  • Only the enrollment number and DOB leave the browser to query the examination server.
  • Requests are sent directly to the official university website.
  • No permanent database records are created.
  • Temporary exports are stored under a 30-minute Time-To-Live (TTL) expiration.
5

Step 5: Monitor Live Bulk Processing

Watch real-time progress on the interactive dashboard:

  • Progress Indicators: Real-time progress bar, percentage completion, and live counters for Total, Success, Failed, and Skipped.
  • Privacy-Masked Terminal Logs: Enrollment IDs are masked (e.g. ...4001) in the log feed.
  • Safe Cancellation: Click Cancel Processing anytime to stop querying without losing previously extracted students.
  • Retry Options: Click individual "Retry" links on failed students or click Retry All Failed.
6

Step 6: Verify Extracted Marks & Integrity

The built-in verification engine automatically inspects extracted results:

  • Marks Boundary Checks: Flags records where obtained marks exceed maximum marks.
  • Negative Marks Alert: Detects invalid negative values.
  • Unpublished/Missing Marks: Flags incomplete records without inserting misleading silent zeroes.
  • Integrity Badges: Verified students receive a green badge; students with notices show an alert icon with details.
7

Step 7: Download Reports & Packages

Download your complete academic result dataset in your preferred formats:

  • Consolidated Excel (.xlsx): Contains 4 sheets — Master Results, Topper Rankings (tied competition rank 1224), Performance Statistics (average, median, pass rate), and Verification Notices. Protected against CSV formula injection.
  • Subject-Wise Excel (.xlsx): Separate tab per subject detailing Theory, Practical, and Sessional splits.
  • Marksheets Archive (.zip): Clean ReportLab-generated provisional academic performance report PDFs for every student.
  • Complete Package (.zip): Consolidated Excel, Subject Sheets, and all student PDFs in one unified archive.
8

Step 8: Manage Local Browser History

Your past processing sessions are stored exclusively in your browser's localStorage.

  • Only anonymized metadata is stored: Job ID, Date/Time, University Portal, and Record Count.
  • No student names or academic marks are stored in history.
  • You can delete individual history entries or click Clear All History anytime.
  • Clearing browser storage or browsing in private/incognito mode removes local history automatically.

Common Issues & Troubleshooting

Invalid Excel File

Ensure the file is a valid .xlsx or .xls workbook and is not password-protected.

Missing Column Mapping

If your header is unusual, manually choose the column representing Enrollment/Roll Number in the Step 2 mapping dropdown.

Duplicate Roll Numbers

Duplicate rows are detected automatically. Check the duplicates count chip; duplicate rows are highlighted in the preview.

Unsupported University Portal

If your portal is not currently supported, use our Demo University connector for testing or request a custom adapter via our contact channels.

University Server Unavailable

Official examination portals often experience heavy traffic during result declarations. Wait a few minutes and click "Retry All Failed".

CAPTCHA or Login Restrictions

Portals requiring interactive CAPTCHAs, OTPs, or student credentials cannot be automated by design.

Student Record Not Found

Verify that the roll number and DOB format match the exact formatting expected by the university portal.

Download Link Expired (404)

Generated export files expire after 30 minutes under our privacy lifecycle policy. Please re-run the batch to generate fresh downloads.

How It Works

Architectural workflow of SkillSum ResultSetu

1. Client-Side Excel Parsing

When you select or drop a student Excel file, it is processed directly in your browser using xlsx.full.min.js. The application detects columns, cleans whitespace, checks for duplicate roll numbers, and displays a 10-row preview without uploading the file to any server.

2. University Portal Adapter Matching

The examination portal URL is checked against our connector registry. Validated URLs are checked against SSRF security guards blocking internal/loopback IPs. Compatible adapters (e.g. BTEUP, standard demo) configure the appropriate request payloads.

3. Automated Bulk Extraction Engine

Upon your explicit consent, student identifiers are sent to the backend worker. The connector dispatches polite requests with built-in delays, extracts subject-wise scores, calculates overall percentages, and verifies marks integrity.

4. Dynamic Workbooks & Standardized PDFs

Results are structured into OpenPyXL workbooks with sanitized formula cells, competition rankings (1224), and summary statistics. Individual provisional performance reports are formatted using ReportLab.

5. 30-Minute Automatic Purge

Export packages are saved in a temporary session directory. A background cleaner loop purges all files after 30 minutes, ensuring strict privacy.

Frequently Asked Questions

Practical answers regarding processing, security, and formats.
Is SkillSum ResultSetu really 100% free? ▾
Yes. It is published under the permissive MIT License by SkillSum Innovations. There are no paid tiers, subscription plans, API fees, or hidden costs.
Do I need to register or create an account? ▾
No. There is no user registration, login, session database, or password system. You can open the utility and start processing immediately.
Is student personal data stored on your servers? ▾
No permanent student records are stored. When using browser-local parsing, your original Excel spreadsheet is processed inside your browser. Query results and marksheets generated during a session are stored in a transient temporary directory with an automatic 30-minute time-to-live (TTL) expiration, after which they are permanently deleted.
What Excel formats are supported? ▾
The tool supports standard Microsoft Excel formats: .xlsx (modern XML-based) and .xls (legacy binary format).
What happens if some student queries fail or time out? ▾
Failed records are clearly flagged in the live stream table with error reasons (e.g. Record Not Found, Timeout, or Alert). You can click the "Retry" button on individual students or use "Retry All Failed" without having to re-process the entire batch.
Can this bypass university CAPTCHAs or firewalls? ▾
No. This application respects university website terms, access restrictions, rate limits, and security controls. It does not bypass authorization or anti-bot protections.

Privacy Policy

Last updated: November 2026 • SkillSum Innovations

This Privacy Policy accurately reflects the technical implementation of SkillSum ResultSetu, an independent utility provided by SkillSum Innovations.

1. Information Processed

The utility processes student academic identifiers provided directly by you, specifically:

  • Student Enrollment Numbers and Roll Numbers.
  • Dates of Birth (when required by the specific university result portal).
  • Student Names and Department/Branch information (if present in your input file).
  • Academic marks and evaluation statuses retrieved from publicly accessible result websites.

2. Browser-Side vs. Server-Side Data Flow

We strictly differentiate between data processed on your client machine and data transmitted to the backend processing service:

  • Browser-Local Processing: Excel file reading, row counting, empty row detection, duplicate checks, and 10-row preview generation occur entirely inside your browser using client-side JavaScript. Your original Excel file is not transmitted to our servers for preview.
  • Server-Side Processing: When you initiate bulk processing, the validated student identifiers (enrollment numbers and DOBs) are transmitted to the backend service to execute the automated portal query, PDF marksheet generation, and OpenPyXL spreadsheet consolidation.

3. Temporary Storage & Automatic Deletion

Generated export files (Excel sheets, PDF marksheets, and ZIP archives) are stored in transient server directories outside public static document roots. An automated background cleaner enforces a strict 30-minute Time-To-Live (TTL) retention policy. All session files are automatically purged from disk upon expiration. You may also click "Start New Batch" to request immediate cleanup.

4. Application Logging Practices

In compliance with privacy-by-design standards:

  • Server activity logs do not record student names, personal details, or academic marks.
  • Student roll numbers in activity feeds are privacy-masked (e.g. ...4001).
  • We do not maintain a permanent database of student records.

5. Zero Tracking & Third-Party Analytics

This website does not include Google Analytics, Facebook Pixel, advertising trackers, cookie-based behavioral profiling, or external telemetry scripts.

6. Third-Party University Websites

When querying results, the application interacts directly with official university examination servers. Those third-party portals operate under their own independent privacy notices and terms.

Data Handling & Retention Lifecycle

Documenting the actual lifecycle of temporary files and memory caches.

We believe in transparent engineering. Here is the exact data lifecycle implemented in the codebase:

1. Client-Side Parsing Phase

  • Location: User web browser memory (RAM).
  • Action: xlsx.full.min.js extracts row objects and column names.
  • Persistence: Discarded immediately when you close or refresh the page. Never saved to local storage or server disk.

2. Transient Processing Session

  • Location: Server temporary folder (temp_storage/{job_id}/).
  • Contents: Generated provisional marksheet PDFs (marksheets/*.pdf) and exported Excel workbooks (exports/*.xlsx, exports/*.zip).
  • Access Protection: Stored outside public static web roots; accessible only via validated session IDs (job_id sanitization guards against path traversal).

3. 30-Minute Automatic Purge (TTL)

  • Implementation: The backend BatchProcessor runs an active background daemon thread (_retention_cleaner_loop) every 60 seconds.
  • Policy: Any session directory older than 30 minutes (JOB_RETENTION_MINUTES = 30) is completely deleted using shutil.rmtree.
  • Manual Trigger: Users can release their storage immediately by clicking "Start New Batch" or triggering DELETE /api/cleanup/{job_id}.

4. Database Status

The application operates with zero persistent database servers (no SQLite, PostgreSQL, MongoDB, or MySQL). All job state exists in active memory and volatile temporary directories during processing.
